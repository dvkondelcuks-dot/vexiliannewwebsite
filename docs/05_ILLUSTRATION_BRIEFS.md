# 05_ILLUSTRATION_BRIEFS.md

## Purpose

This document defines the illustration system for the Vexilian hospitality homepage.

The goal is to create a hand-drawn founder notebook feel while maintaining Stripe-level clarity.

The illustrations must explain commercial leakage. They must not decorate randomly.

## Illustration Style Doctrine

The illustration style should feel like:

> A premium founder notebook used to map where hospitality reservations leak.

It should not feel like:

1. A cartoon brand
2. A children’s sketchbook
3. A generic SaaS dashboard
4. AI-generated hospitality stock art
5. Random doodles on a page

## Visual Personality

1. Slightly imperfect
2. Structured
3. Premium
4. Calm
5. Commercial
6. Hospitality-specific
7. Founder-made
8. Sharp enough for a serious owner

## Core Visual Ingredients

Use:

1. Hand-drawn SVG lines
2. Thin arrows
3. Soft paper panels
4. Scribbled circles
5. Marginal notes
6. Broken path lines
7. Simple hospitality icons
8. Neon green as a precision mark
9. Dark graphite as the main base
10. Warm paper for note surfaces

Avoid:

1. Thick childish marker lines
2. Random squiggles
3. Sketchy faces
4. Cartoon owners
5. Cartoon guests
6. Photo-real AI hotels
7. Overly decorative icons
8. Fake charts with made-up numbers
9. Full neon green sections
10. Template illustration packs

## Colour Rules

Main ink:

`#FAFAFA` on dark sections and `#0A0A0A` on paper sections.

Paper:

`#F4EFE7`

Muted secondary:

`#D8CBB8`

Neon green:

`#D0FF00`

Neon usage:

1. Main active path
2. Leak highlight
3. CTA-linked visual cue
4. Small status dot
5. “pazūd šeit” mark

Neon must remain around 10 percent visual presence.

## Typography in Illustrations

Use handwritten-style labels only for annotations.

Examples:

1. “pazūd šeit”
2. “nav follow-up”
3. “klusais mēnesis”
4. “atnāca no Booking?”
5. “kam rakstīt tālāk?”

Do not use handwritten font for main section headings, body text, CTA, form labels, or pricing.

## Illustration 1: Hero Messy Signals

### Purpose

Show that client interest arrives from multiple places and the owner cannot clearly see what becomes a reservation.

### Placement

Hero right side on desktop. Below hero copy on mobile.

### Visual Composition

Central question in a rough circle:

> Kur pazuda rezervācija?

Around it, five to seven cards:

1. Instagram DM
2. Booking.com pieprasījums
3. Telefona zvans
4. E-pasts
5. Mājaslapas forma
6. Optional: Facebook ziņa
7. Optional: WhatsApp jautājums

Cards should be slightly offset, as if placed by hand on a dark desk or warm paper board.

### Required Objects

1. Message card
2. Booking request tag
3. Phone call note
4. Email slip
5. Website form mini-card
6. Broken arrow toward “Rezervācija”
7. One neon green path line that breaks

### Emotional Tone

Slightly chaotic but premium.

The owner should recognize the mess without feeling attacked.

### Copy Labels

Use small notes:

1. “jautāja par datumu”
2. “nav nākamā soļa”
3. “zvans palika atmiņā”
4. “forma bez konteksta”
5. “kurš kanāls?”

### What Not To Draw

1. Dashboard
2. Laptop
3. Smartphone mockup overload
4. Generic hotel building
5. Smiling cartoon owner
6. Huge warning icons

## Illustration 2: Reservation Leakage Path

### Purpose

Show that reservations leak across a path, not in one mysterious moment.

### Placement

Leakage Map section.

### Path

> Redzamība → Pieprasījums → Atbilde → Follow-up → Rezervācija → Atkārtots viesis

### Visual Composition

A horizontal or slightly curved path with six nodes.

Some lines are broken. One green overlay shows the fixed path.

Under each node, include one small annotation.

### Required Nodes

1. Redzamība
2. Pieprasījums
3. Atbilde
4. Follow-up
5. Rezervācija
6. Atkārtots viesis

### Leakage Notes

1. Saturs nepaskaidro, kāpēc rezervēt tagad.
2. Pieprasījums nav novērtēts.
3. Atbilde neved uz lēmumu.
4. Nav nākamā kontakta.
5. Nav redzams avots.
6. Viesis netiek atgriezts.

### Emotional Tone

Clarity.

This illustration should feel like the moment chaos becomes understandable.

### What Not To Draw

1. Sales funnel triangle
2. Corporate pipeline chart
3. Tech architecture
4. Fake revenue numbers
5. Overcomplicated arrows

2. Panic visuals

## Illustration 4: Booking/Airbnb Dependence

### Purpose

Explain that platforms provide visibility but do not automatically create the owner’s own client path.

### Placement

Booking/Airbnb objection section.

### Visual Composition

Two-side map:

Left side:

Platform visibility.

Right side:

Owner-controlled guest path.

A guest enters from Booking/Airbnb, but without the owner path the line fades. With the owner path, the line continues into repeat guest.

### Required Objects

1. “Platformas redzamība” note
2. “Jūsu klientu ceļš” note
3. Guest path line
4. Fading line without follow-up
5. Green continuation line with follow-up
6. Old guest reactivation loop

### Copy Labels

1. “atrada jūs”
2. “bet vai varat uzrunāt vēlreiz?”
3. “tiešais ceļš”
4. “atkārtots viesis”

### Emotional Tone

Respectful, not anti-platform.

### What Not To Draw

1. Platform logos unless legally and visually appropriate
2. Aggressive anti-Booking message
3. “cut out platforms” message
4. Fake commission savings claims

Show what clarity looks like for the owner without using technical dashboard language.

### Required Cards

3. Avots
4. Vērtība
5. Statuss
6. Nākamais solis
7. Klusā mēneša iespēja
8. Atkārtotais viesis

> 4 šonedēļ

> 2 interesenti

Avots:

> Instagram / Booking / zvans

Statuss:

> gaida lēmumu

Nākamais solis:

> rakstīt rīt

### Emotional Tone

Relief and control.

2. Complex analytics charts
3. BI dashboard
4. Software product UI
5. Massive grid of numbers

## Animation Rules

Motion should feel calm and intentional.

Allowed:

1. Signal cards gently floating
2. Path line drawing itself
3. Small leakage mark appearing
4. Calendar note sliding in subtly
5. Owner board cards softly revealing

Avoid:

1. Fast bouncing
2. Excessive parallax
3. Card spinning
4. Neon flicker
5. Heavy scroll-jacking
6. Animations that distract from reading

Reduced motion must be respected.

## SVG Construction Rules

1. Prefer simple inline SVGs.
2. Lines should use rounded caps and joins.
3. Avoid excessive path complexity.
4. Keep marks readable on mobile.
5. Use scalable viewBox sizes.
6. Avoid image dependencies for core diagrams.
7. Keep labels as accessible text where possible.
8. Do not embed unlicensed fonts in SVG.

## Illustration QA Checklist

Before accepting each illustration, ask:

1. Does it explain a specific commercial idea?
2. Does it feel premium, not childish?
3. Is the hand-drawn style controlled?
4. Is neon green limited and meaningful?
5. Is the visual hospitality-specific?
6. Does it avoid technical dashboard language?
7. Does it work on mobile?
8. Does it avoid fake data?
9. Does it make the audit CTA feel logical?
10. Would a serious owner understand it within three seconds?
